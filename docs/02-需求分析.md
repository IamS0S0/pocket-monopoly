# 需求分析

## 用户与使用场景

用户为 2–4 人本地同屏桌游玩家，或希望与 AI 对战的单人玩家。课堂验收时需能快速完成一局并说明内部实现。真人共用鼠标 / 键盘，AI 不使用远程服务。

## 功能需求与验收条件

| 编号 | 需求 | 验收条件 | 实现阶段 |
| --- | --- | --- | --- |
| F01 | 游戏配置 | 3 张地图、4 个角色、2–4 个座位，每座位可独立选择真人 / AI，默认 30 回合 | ① |
| F02 | 棋盘 | 地图格子分布不同，包含起点、地产、事件、机会、监狱与税收 | ② |
| F03 | 移动 | 掷骰有 3D 动画，角色逐格跳跃，镜头平滑跟随，禁止重复触发 | ② |
| F04 | 地产 | 购买、付租、升级、查看地契，升级提高租金 | ③ |
| F05 | 随机事件 | 金币增减、传送、暂停回合，展示文案和反馈 | ④ |
| F06 | 破产与排名 | 不足支付先变卖，仍不足则退场；剩一人或到达上限结束 | ④ |
| F07 | AI | 根据资金余量、性价比与升级收益决策；异常时安全回退 | ⑤ |
| F08 | 体验 | 金币变化动画、漂浮文字、回合高亮、日志、音效开关及胜败画面 | ⑥ |
| F09 | 完整验证 | 完成真人局和 AI 局各一次，记录测试用例的预期及实际结果 | ⑦ |

## 配置边界

- 回合上限为 5–100 的整数，5 回合便于短时演示。
- 允许全真人、真人与 AI 混合、全 AI 观察局。
- 每个角色最多被一个座位占用；选择已占用角色时交换双方角色。
- 调小人数保留剩余座位设置，调大人数使用尚未占用的角色补齐。
- 第①阶段初始金币为 1,500；经济平衡参数在地产阶段统一设计。

## 非功能需求

- 纯前端，可静态部署，渲染资源由代码生成。
- 状态与规则不依赖 DOM / Three.js，便于单元测试。
- 布局适应桌面和窄屏；键盘可操作原生按钮与选择框，弹窗使用原生 dialog。
- 切换主题释放旧场景 GPU 资源，设备像素比最多为 2；尊重减少动态效果设置。
- 第②阶段起建立单一回合状态机，明确动画中断、破产和重复操作的处理策略。
