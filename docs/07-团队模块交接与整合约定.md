## 已实现的接入接口

| 接口 | 职责 |
| --- | --- |
| createGameState(config) | 校验并创建初始状态 |
| createBoard(mapId) | 生成普通对象格子数组，含 id/index/type/name/x/z/rotation |
| TurnEngine.snapshot() | 返回独立状态快照，供 UI 展示 |
| beginRoll() | 仅等待掷骰时接受，返回 token/value/path/playerIndex |
| beginMovement(token) | 骰子动画完成后转入移动状态 |
| completeStep(token, position) | 仅接受下一格的位置确认 |
| land(token) | 全部移动结束后记录落点，转为等待结束 |
| endTurn() | 仅落定后切换玩家，完成一轮后增加 round |
| recover(token) / dispose() | 动画失败回滚 / 永久拒绝旧局动作 |
| BoardView.roll / hop | Promise 返回动画完成与否；取消时返回 false |
| mountMenu 的 onStart | 成功后切换页面，不再返回摘要数据 |

## B 模块接入位置

在 core/engine.js 的 land 完成移动验证后接入格子规则。地产、税收等效果由纯逻辑模块修改状态，UI 根据状态提供购买或升级决策。应在所有落格效果与决策完成后才允许 endTurn；不要让 UI 直接修改金币。当前没有起点奖励和资产估值，需由 B 统一定义并测试。

## C 模块接入位置

AI 根据状态快照提交候选动作，通过与真人共用的引擎接口执行。当前所有座位手动操作；接入 AI 后仅自动控制 type=ai 的座位。保留动作锁和取消机制，避免延迟回调作用于新局。动画音效可消费规则状态和动作结果，不能重新随机决定点数。

## 整合检查

每次同步先检查工作区，禁止覆盖他人未提交文件。新电脑用 npm ci 安装，运行 npm test 与 npm run build，再在浏览器验收。更新 README 的功能对应表与测试报告，阶段完成后暂停确认。

当前回合上限只结束移动演示，不进行完整资产排名。第⑦阶段仍需完整真人局、AI 局、长期稳定性、公开部署及真实用户反馈。
