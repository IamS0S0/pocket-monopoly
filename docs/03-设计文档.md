# 设计文档

## 当前模块职责

| 层 | 模块 | 责任与边界 |
| --- | --- | --- |
| 数据 | `data/maps.js`、`data/characters.js` | 主题与角色描述，无框架依赖 |
| 纯逻辑 | `core/config.js` | 默认配置、人数调整、角色交换和非法输入防御 |
| 纯逻辑 | `core/state.js` | 从有效配置创建独立状态，不读取 UI、不播放动画 |
| 渲染 | `render/character.js` | 基础几何体组成四款 Q 版角色 |
| 渲染 | `render/preview.js` | 微缩主题预览、光照、动态与资源生命周期 |
| 界面 | `ui/menu.js` | 输入收集、选中反馈、帮助和配置摘要 |
| 编排 | `main.js` | 注入回调，连接界面、纯逻辑与渲染 |

当前预览中的 24 个装饰格仅用于展示主题，并非已经实现的规则棋盘；第二阶段将把真实棋盘数据独立出来，再交给渲染层使用。

## 核心数据

```text
配置：mapId、roundLimit、players[]
玩家配置：id、name、type（human / ai）、characterId
游戏状态：phase、mapId、roundLimit、round、currentPlayerIndex、players、properties、logs
玩家状态：玩家配置 + coins、position、bankrupt、skippedTurns
```

创建状态前统一校验。初始状态与配置无共享玩家对象，后续对局变化不会污染大厅设置。人数调整与角色选择返回复制后的配置，简化不变式验证。

## 后续模块规划（尚未实现）

- `core/engine.js`：回合状态机与动作令牌。
- `core/dice.js`：点数生成，可注入随机源方便测试。
- `core/property.js`：购买、租金、升级和资产估值。
- `core/event.js`：事件抽取与规则执行。
- `core/bankrupt.js`：变卖次序、清偿、破产与退场。
- `ai/strategy.js`：启发式候选决策；不直接修改状态，异常时默认放弃可选行动。
- `render/board.js`、`render/dice.js`：棋盘与骰子表现。
- `ui/hud.js`、`ui/deed.js`、`ui/results.js`：对局信息、地契与排名。

计划的回合状态：等待掷骰 → 掷骰 → 移动 → 落格处理 → 等待决策 → 回合结束。结束状态拒绝新动作。每个异步动画绑定局次 / 动作令牌，过期回调不得推进回合。破产时取消该角色待执行动画并由规则层决定下一位玩家。

## 渲染生命周期

主题变更先移除旧 Group，遍历释放几何体与材质，再生成新主题。窗口尺寸通过 ResizeObserver 更新相机比例。热更新时停止动画循环、断开观察器并释放 WebGLRenderer。WebGL 不可用时显示文字提示，配置功能仍可使用。

## 答辩讲解路径

从 `menu.js` 的「集结出发」点击处理开始，沿 `onStart` 进入 `createGameState`，展示 `validateConfig`，说明界面不能跳过规则校验。随后展示 `createCharacter`，解释 Q 版造型如何通过球体、胶囊体与圆柱体组合。最后运行 `npm test`，说明纯逻辑可以脱离浏览器测试。
